==============================================================================
GUIA: ENTRENAR Y AFINAR EL DETECTOR DE PLACAS, LOCALMENTE O CON DOCKER
==============================================================================

1. IMAGENES SOLICITADAS Y ETIQUETAS

   Origen: dataset/openimages_plates_ecuatorianas/
   Contiene 8.000 recortes SINTETICOS de placas: 7.200 train y 800 val.
   No son fotos reales de vehiculos de Open Images, aunque la carpeta tenga
   ese nombre. Sus etiquetas son de pose (caja + cuatro esquinas).
   El data.yaml original apunta a otra carpeta; NO usarlo para el detector.

   Las etiquetas ya existen: NO hay que volver a autoetiquetar estas imagenes.
   Preparar una copia de deteccion que conserva las imagenes y cajas originales:

   .\services\anpr\.venv\Scripts\python services\anpr\scripts\prepare_plate_dataset.py

   Resultado: dataset/detector_ecuatorianas/
   - images/{train,val}/ y labels/{train,val}/: etiquetas YOLO de 5 columnas.
   - data.yaml: rutas portables entre Windows y Docker.
   - provenance.json: auditoria, huellas SHA-256 y limitaciones.
   - preview/contact_sheet.jpg: muestra de cajas verdes para revision visual.

   Se conserva el reparto existente 90/10. No se inventa una particion test.
   El preparador rechaza destinos existentes para no mezclar corridas; si la
   copia ya esta preparada, continuar directamente con el siguiente paso.

2. VALIDAR Y ENTRENAR EN WINDOWS (TERMINAL EN LA RAIZ DEL PROYECTO)

   Validar sin entrenar:

   .\services\anpr\.venv\Scripts\python services\anpr\scripts\train_plate_detector.py --validate-only

   Afinar desde el detector de placas actual (evita empezar desde COCO):

   .\services\anpr\.venv\Scripts\python services\anpr\scripts\train_plate_detector.py --data dataset/detector_ecuatorianas/data.yaml --weights services/anpr/models/license_plate_detector.pt --nombre ecuatorianas --epochs 30 --imgsz 512 --batch 8 --device cpu --workers 0 --threads 4 --export-onnx

   --epochs controla el maximo de epocas. --patience permite parada temprana.
   --multi-scale 0.25 cambia la resolucion por lote; las aumentaciones incluyen
   escala, rotacion, perspectiva y brillo, sin invertir los caracteres.
   --freeze 10 permite congelar las primeras diez capas en un afinamiento.
   No implica precision garantizada a una distancia concreta.

3. ENTRENAR ESTANDO DOCKERIZADO: SI SE PUEDE

   Abrir Docker Desktop en modo contenedores Linux y, desde la raiz, ejecutar:

   docker compose -f docker-compose.train.yml build train
   docker compose -f docker-compose.train.yml run --rm train --validate-only
   docker compose -f docker-compose.train.yml up -d train
   docker compose -f docker-compose.train.yml logs -f train

   NOTA: run con argumentos sustituye el comando del servicio. --validate-only
   funciona porque el script usa dataset/detector_ecuatorianas por defecto.
   up inicia la configuracion completa: 30 epocas, 512 px, batch 8, CPU y ONNX.
   El contenedor de entrenamiento es independiente del motor FastAPI.
   Los montajes conservan datos, modelos y resultados en el disco del host.
   Eliminar el contenedor no elimina esos archivos.

   Reanudar una corrida interrumpida, sustituyendo RUTA por su checkpoint:

   docker compose -f docker-compose.train.yml run --rm train --data /workspace/dataset/detector_ecuatorianas/data.yaml --resume /workspace/dataset/runs/RUTA/weights/last.pt --device cpu --workers 0 --export-onnx

   Para afinar otra vez con imagenes nuevas, preparar un dataset revisado y usar
   --weights /workspace/services/anpr/models/NOMBRE_candidato.pt.
   --resume recupera una corrida interrumpida; --weights inicia un nuevo ajuste.
   Mas instrucciones y activacion del motor: docs/ENTRENAMIENTO_DOCKER.md.

4. RESULTADOS Y USO EN EL MOTOR

   dataset/runs/<corrida>/weights/best.pt: mejor checkpoint de validacion.
   dataset/runs/<corrida>/weights/last.pt: checkpoint para reanudar.
   dataset/runs/<corrida>/results.csv: metricas por epoca.
   services/anpr/models/<corrida>_candidato.pt: candidato con nombre unico.
   services/anpr/models/<corrida>_candidato.json: datos y metricas de la corrida.
   services/anpr/models/<corrida>_candidato.onnx: exportacion de tamano dinamico.
   services/anpr/models/<corrida>_candidato.benchmark.json: medicion de ONNX.

   Se verifica una inferencia con ONNX Runtime. Exportar NO garantiza menos
   de 10 ms: depende del equipo, resolucion y carga. El benchmark solo mide
   la red; no incluye video, preprocesamiento ni OCR.

   El entrenamiento genera un candidato; no sustituye automaticamente
   services/anpr/models/license_plate_detector.pt. Comparar en fotografias
   reales independientes antes de activarlo; los sinteticos solos no bastan.
   El motor carga pesos al arrancar: cambiar el archivo o PLATE_MODEL_PATH
   requiere reiniciar el servicio, no existe aprendizaje continuo automatico.

5. FOTOS REALES PARA UNA SIGUIENTE MEJORA

   Guardar fotos completas en dataset/raw/, preferiblemente agrupadas por
   vehiculo y dia. Se pueden crear subcarpetas de 1_metro, 2_metros, 3_metros,
   5_metros y 8_metros. Tomar vistas frontales, inclinaciones y distintas luces.
   Cinco o diez fotos por distancia sirven para explorar; para evaluar el motor
   se necesita variedad de vehiculos, fondos, camaras y placas pequenas.

   Para fotos nuevas sin etiquetas, usar scripts/annotate_plates.py, que propone
   cajas a partir de OCR independiente y genera vistas para revision manual.
   Consultar su --help antes de elegir origen, destino y grupos de prueba.
   Conservar el mismo vehiculo/secuencia dentro de una sola particion evita
   evaluar con fotos casi identicas a las del entrenamiento.

   Los recortes sinteticos tambien son utiles para OCR y para el rectificador
   de esquinas. Este procedimiento afina el DETECTOR, no entrena esos otros
   modelos del motor ANPR.
